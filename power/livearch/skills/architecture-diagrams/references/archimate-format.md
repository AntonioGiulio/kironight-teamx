# ArchiMate format (LiveArch)

`architecture.archimate.xml` follows the **Open Group ArchiMate Model Exchange File Format 3.1**.
To import it into Archi: *File → Import → Open Exchange XML Model*. It is regenerated in full.
Reference implementation: `../scripts/render.py`.

## Skeleton
```xml
<?xml version="1.0" encoding="UTF-8"?>
<model xmlns="http://www.opengroup.org/xsd/archimate/3.0/"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.opengroup.org/xsd/archimate/3.0/ http://www.opengroup.org/xsd/archimate/3.1/archimate3_Diagram.xsd"
       identifier="la__model">
  <!-- Generated by LiveArch - catalog=1.0.0 model=3f2a9c1b7d40 -->
  <name xml:lang="en">LiveArch architecture</name>
  <elements>…</elements>
  <relationships>…</relationships>
  <views><diagrams><view identifier="la__view" xsi:type="Diagram">…</view></diagrams></views>
</model>
```

## Elements
- Groups first, then nodes, each ordered by id: `<element identifier="<diagramId>" xsi:type="<type>">`.
- Type of a group: `groupKinds[kind].archimate` (`Grouping`). Type of a node: `kinds[kind].archimate`.
- Children: `<name xml:lang="en">label</name>`, then `<documentation xml:lang="en"><iacType> · <id></documentation>`.

## Relationships
| Source | identifier | xsi:type |
|--------|------------|----------|
| model edge | edge diagramId (`la_e_…`) | `edgeKinds[kind].archimate`, **but** `Access` becomes `Flow` when the target type is not `Artifact` |
| group membership (child group or node) | `la_m_` + sanitize(`<groupId>__<childId>`) | `Aggregation` (source = group) |

Order: edges by id, then memberships by identifier.

## View
- One `node xsi:type="Element"` per element: identifier `la_v_` + sanitize(id), `elementRef` = diagramId.
  Children are **nested** inside their group's node.
- `x`, `y`, `w`, `h` are **absolute** coordinates, equal to the draw.io geometry once relative positions are summed.
  Archi and draw.io therefore show the same layout.
- One `connection xsi:type="Relationship"` per model edge: identifier `la_c_` + sanitize(edge id), `relationshipRef`,
  and `source`/`target` = view node identifiers. Memberships are not drawn: nesting already shows them.

## Known limits
Not every ArchiMate relationship is valid between every element type. `Triggering` and `Flow` between Technology
elements rely on the relationships that ArchiMate 3.1 derives. If Archi rejects an import, file the case and fix the
mapping **in the catalog** (`edgeKinds`), not in the renderer.
